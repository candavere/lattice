Audit AI decisions, not just outcomes.

A seeded multi-agent experiment, replayed from a committed recording. Compare what each agent could actually see against what really happened, and check the evidence rather than trusting a black box.

This page replays recorded evidence. Every frame below is read from a file committed to the repository; your browser never runs a new simulation. Both recordings are checked in CI on every push — replay --verify re-simulates each tick, and a drift gate re-derives the regenerable one from its documented command and byte-compares the result — so a recording that stopped matching the engine would fail the build rather than sit here quietly.

    How to read what you are looking at
    
      
    
        Recorded perception vs. reconstructed sightline
      
    
        infiltration.jsonl is recorded at trajectory schema v5, which stores what each
        agent’s own perception filter produced at the moment it chose its action
        — one Perceptions entry per agent per tick, plus the cone each filter used
        (AgentVision: [2, 2], two graph hops apiece). The agent view here draws that
        record and nothing else, and labels it “recorded perception”. The core’s
        Vision stays unbounded by design: the fog is the agents’, not the
        simulation’s.
      
    
      
    
        demo.jsonl is pinned at schema v3, which predates the field, so it carries no
        fog at all. For that recording the agent view falls back to a
        reconstruction by this page, computed from recorded positions with a 2-hop
        rule, and says so: the chip reads “reconstructed sightline”, never “recorded
        perception”. One page, two recordings, two different answers — each labelled with
        where it came from, and neither presented as the other.
      
    
      
    
        The final frame is the one case a scrubber can get wrong. The episode ended there, so no
        agent ever decided from that world and no perception was recorded for it. The map shows the
        last decision-time view it did act on and says which tick that was, rather
        than passing step 20’s fog off as a fresh reading of the terminal frame.
      
    
      
    
      
    
        
    The moment to watch — ticks 9, 19 and 20
    
        
    
          On the Infiltrator view chip the Treasure Vault is recorded as “last
          known” at ticks 9, 19 and 20, while ground truth keeps it fully lit:
          at tick 9 the Infiltrator is back in the Entry Hall, three hops from the vault; at tick 19
          it has looted both chests and the room goes last known again, and tick 20 — the last
          decision-time view in the file — still shows it dimmed. Step to tick 9, select the
          Infiltrator view chip above the map, and watch the room dim on one map while it
          stays lit on ground truth. The explanation sentence follows the same line.
        
    
        
    
          The Sentry view is the mirror image, and worth stepping to as well: the guard
          records its own post and the entry hall as “last known” at ticks 15 and
          16, and at its final decision-time view (tick 20) it records every room as
          observed. The vault it has not seen since the opening two frames.
        
    
        
    
          Honest framing: on infiltration.jsonl these tiers are the agent’s own
          recorded perception, and lattice replay --verify recomputes all 20 of them and
          fails if one is edited. On demo.jsonl the same tiers are this page’s
          2-hop reconstruction, because that file records no perceptions — so “drops out of
          sight” there always means “out of the reconstructed 2-hop sightline”,
          never “the engine could not see it”. The chip on the map tells you which
          recording you are looking at.

    Reproduce an experiment or verify a recording
    
      
    
        One committed script owns the seed, scenario, tick budget and policy of the
        recording that can be regenerated, and --check proves the committed bytes
        are still what those settings produce — that is the drift gate CI runs. The other
        recording is deliberately pinned at an older schema and is verified but never
        rewritten; the script header says why.
      
    
      
      
        
    • 
          Re-derive the regenerable recording and both rendered SVGs, and verify the pinned one
          (add --check to verify without writing)
          
      ./scripts/regenerate-site-demos.sh
      
        
      • 
        
    • 
          The simulate line it runs for the regenerable recording — the
          infiltration scenario (Sentry vs Infiltrator). The sampling scenario (agent 0 = MCTS;
          see --agent in
          docs/CLI.md)
          
      dotnet run --project Cli -- simulate --seed 42 --scenario infiltration --steps 100 --out infiltration.jsonl
dotnet run --project Cli -- simulate --seed 42 --agent mcts --steps 30 --out demo.jsonl
      
        
      • 
        
    • 
          Render any recorded trajectory as an animated SVG
          
      dotnet run --project Cli -- render --trajectory infiltration.jsonl --format svg --out infiltration.svg
      
        
      • 
        
    • 
          Prove a recording is honest: `--verify` re-feeds each recorded turn through the current
          engine and compares every re-serialized result
          
      dotnet run -c Release --project Cli -- replay infiltration.jsonl --verify
      
        
      • 
        
    • 
          Replay it in a browser: drop the .jsonl file onto the replay viewer above.
        
      • 
      
    
      
    
        Every command is seeded and deterministic under the current engine: the same command and
        engine re-create the same file, byte for byte. That is how
        infiltration.jsonl is proven current in CI;
        demo.jsonl is pinned at schema v3 on purpose and is verified instead of
        regenerated. replay --verify re-simulates both tick by tick — including
        each tick’s state hash — so a recording that stopped matching this engine would
        fail the build rather than sit here quietly. The viewer always shows the committed file
        exactly as it was recorded.
