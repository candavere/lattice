About the “fog” on this page

The treasure recordings were captured with unbounded vision (the study suite used Vision = -1), so the engine never recorded “fog” — there is no fog field in the recording. The dashed sightline the agent view draws is a reconstruction by this page, computed from recorded positions using a 2-hop rule (“which rooms could a 2-hop agent see?”). It is the page’s honest answer to an “audit it yourself” prompt — not a claim about what the engine knew, and never “the Vault was unseen”. On the Agent view it is labelled “reconstructed sightline”, not “recorded fog”.

This page replays recorded evidence. Every frame below is read from a committed recording; your browser does not run a new simulation.

The moment to watch — ticks 9, 19 and 20

On the Infiltrator view chip the Treasure Vault dims to “last known” at ticks 9, 19 and 20, while ground truth keeps it fully lit: at tick 9 the Infiltrator is back in the Entry Hall, three hops from the vault, four ticks after it claimed the chest there; at ticks 19-20 it has looted both chests and the room is last known again. On the Sentry view chip the vault dims only on the final tick, 20. Step to tick 9, select the Infiltrator view chip above the map, and watch the room dim on one map while it stays lit on ground truth. The explanation sentence follows the same line.

Honest framing: this is page-reconstructed sight from recorded positions. The engine recorded no fog (unbounded vision); the dashed 2-hop ring is this page’s reconstruction, so “drops out of sight” here always means “out of the reconstructed 2-hop sightline” — never “the engine could not see it”.

    Reproduce an experiment or verify a recording
    
      
      
        
    • 
          Record the infiltration scenario (Sentry vs Infiltrator) — the fixed-content demo
          
      dotnet run --project Cli -- simulate --seed 42 --scenario infiltration --steps 100 --out infiltration.jsonl
      
        
      • 
        
    • 
          Or the classic sampling scenario (agent 0 = MCTS; see --agent in
          docs/CLI.md)
          
      dotnet run --project Cli -- simulate --seed 42 --agent mcts --steps 30 --out demo.jsonl
      
        
      • 
        
    • 
          Render any recorded trajectory as an animated SVG
          
      dotnet run --project Cli -- render --trajectory infiltration.jsonl --format svg --out infiltration.svg
      
        
      • 
        
    • 
          Prove a recording is honest: `--verify` re-feeds each recorded turn through the current
          engine and compares every re-serialized result
          
      dotnet run -c Release --project Cli -- replay infiltration.jsonl --verify
      
        
      • 
        
    • 
          Replay it in a browser: drop the .jsonl file onto the replay viewer above.
        
      • 
      
    
      
    
        Every command is seeded and deterministic under the current engine: the same command and
        engine re-create the same file. The committed recordings on this page were re-recorded with
        these commands on the engine that ships in this repository, and
        replay --verify re-simulates both of them tick by tick — including each
        tick’s state hash — in CI, so a recording that stopped matching this engine
        would fail the build rather than sit here quietly. The viewer always shows the committed
        file exactly as it was recorded.
